simar-ui v1 beta

A dependency-free UI library built on native HTML: forms, navigation, data display and layout. Every component is a real HTML element underneath. Press HTML under any component to see how it was added to the page.

Getting started

Install

Two files, no build step. Put these in the page, then write the markup below or the <simar-*> tags.

Or npm install simar-ui and import simar-ui/css and the script. Everything is configured with HTML attributes, listed under Configuration.

Declarative tags

Write a short tag and the script expands it into the markup shown in the sections above, so inputs still submit with their form. Options are attributes named like the native ones. These need JavaScript; the plain markup above doesn't.

Accessibility

simar-ui is built to be fully accessible, and checked on every change. Every control is a native element, so the keyboard, focus and screen-reader behavior comes from the browser, and the styling sits on top.

  • Keyboard. Everything is reachable and operable, and every stop shows a focus ring in both themes.
  • Names. Every control has a real label. Icon-only keys need an aria-label, and the library warns in the console, and outlines the control on localhost, if one is missing.
  • Color. Text meets WCAG AA in light and dark and every highlight. State is never color alone: it also has a check mark, a position, a pattern, or words.
  • No dragging required. Anything you can drag you can also set with a click or the keyboard.
  • Motion and contrast modes. prefers-reduced-motion and Windows High Contrast are supported, and everything degrades to native controls without JavaScript.
  • Tested. npm run test:a11y runs axe, contrast, WCAG 2.2 and keyboard checks in light and dark. Real screen readers, touch and Safari/Firefox still need a human pass.

Customize

Theme and color

Light and dark follow the system, or you choose with data-theme on <html> or any element. One value, --lit, recolors every lit part. Use the controls at the top of the page to try both.

Design tokens

Everything about shape and depth is a CSS custom property, set once on :root or on any element to change just that part of the page. The global ones (--radius, --depth) move everything together; each component also has its own (--key-radius, --card-radius) that you can set on its own, and that falls back to the global one when you don't. The data-style presets are just bundles of these values. Move the sliders to see the result, then copy the CSS.

Content

Card

A self-contained block of content: an <article> with an optional image, a heading and words, and a footer for actions. Lay cards in a blurb-grid and they wrap to fit. To make the whole card a link, put one link with card__link in the heading: a click anywhere on the card follows it, but a keyboard and a screen reader still meet a single link named by the heading. Buttons in the footer stay separate.

Carousel and gallery

A row of slides that scrolls sideways and snaps, on plain HTML and CSS, so it works without script: swipe it, focus it and use the arrow keys, or follow the numbered links (each points at a slide's id). Script adds Previous and Next keys, Home and End on the focused row, and a polite "Slide 2 of 4" status. It follows the WAI-ARIA Carousel pattern: a region with aria-roledescription="carousel" and each slide a group named "1 of 4". Nothing moves on its own unless you set data-autoplay; then there is a Pause key, it stops while the pointer or focus is inside, and it does not start at all for visitors who asked for reduced motion. Add carousel--multi for a gallery that shows several at once.

Embed

A responsive frame for content you don't control the size of: an <iframe> (a map, a video player, a document), an <embed>, an <object>, a <canvas> or a <video>. It keeps an aspect ratio (16:9, or embed--4x3, embed--1x1, embed--21x9) and scales with its container, so it never overflows a phone. An <iframe> must have a title, which is its name for a screen reader.

Embed

Layout and breakpoints

Mobile first, like Bootstrap: a class with no breakpoint applies everywhere, and one with a breakpoint (md) applies from that width up. The breakpoints are sm 36rem, md 48rem, lg 62rem, xl 75rem and xxl 87.5rem (576, 768, 992, 1200 and 1400px at the default size), and they are in rem, so they follow the reader's text size. Resize the window to see the columns below change. The class names and breakpoint approach are borrowed from Bootstrap, so they will feel familiar.

Lists

Native <ul>, <ol> and <dl>, styled. A bare list is left to the browser, so add list. The markers take the theme's highlight color. list--divided puts a line between items (a list group), a description list puts each term beside its detail (list--stacked puts the detail underneath), and list--plain drops the markers; give a plain or divided list role="list" too, because Safari with VoiceOver stops announcing a list once its markers are gone.

Media

Images, video and audio on the native elements. Put media on a <figure> and its picture scales down to fit, keeps its shape and gets the same rim as other surfaces. Give every image its width and height so the page does not jump as it loads, and an alt that says what it shows. Add media--16x9, media--4x3 or media--1x1 to crop to a fixed shape. Video and audio keep the browser's own controls, which a keyboard and screen reader can use; a recording also needs captions or a transcript.

Quotes

A quotation is a <blockquote> inside a <figure class="quote">, with who said it in the <figcaption>. The dash before the name is decoration, so it is not read out. Add quote--pull for a pull quote.

Avatar

A person or thing as a small round picture or initials. It is plain content with no role of its own. A photo is an <img>: its alt is the name when the avatar stands alone, and empty when the name is written beside it, so it is not read twice. Initials are text: the letters are hidden from assistive tech and the name is visually hidden text, so a screen reader says "Ellen Ripley", not "E R". Beside a visible name, hide the whole avatar with aria-hidden="true". A link or button around one keeps a 24px or larger target and a focus ring. A group overlaps them and can end with a count that says how many more.

Tile list

Rows with a leading avatar or icon, a title with a line of detail, and a trailing action or note. It is a plain <ul>. The leading avatar is hidden from assistive tech because the name is written beside it, the title can be a link, and the trailing action is an ordinary key whose aria-label says what it does and to whom. A short note (a time, a count) can stand in for the key with tile__meta.

Skeleton

Grey shapes that stand where content will be while it loads. The wrapper is a polite role="status" with words for assistive tech ("Loading the crew"); the shapes are decoration (aria-hidden), so nothing is read twice. Swap the wrapper for the real content when it arrives. The shimmer stops under prefers-reduced-motion, and in forced colors the shapes get a plain outline.

Empty state

What a list, search or page says when there is nothing to show, and what to do next: a heading (pick the level that fits the page), a sentence and one action. The icon is decoration. Say what is empty and why, and give a way forward ("Clear search", not "OK").

Steps

Where you are in a short sequence. It is an ordered list, one item per step: done (a check), current (aria-current="step") and upcoming (an outline). State is a shape and a word, never color alone: each mark is a check, a filled number or an outlined number, and a visually hidden ", completed" or ", current step" follows the name. On a narrow screen the list stacks. The wizard builds this list for itself.

Refreshable list

A scrolling list that can be refreshed by pulling it down from the top on a touch screen, or, always, by its visible Refresh key, which is the real control: the pull is only a convenience and nothing needs it. While it works the status says "Refreshing..." and the body is aria-busy; afterwards the status says what happened. The page does the loading: listen for refresh on the element. Without script the bar is hidden and the content is just a list.

Swipe list

Rows with actions, such as Archive and Delete. Without script the actions are ordinary keys on each row, so everything works. With script they sit behind the row and there are three ways to reach them: swipe left (touch and pen only, so a mouse can still select text and the page still scrolls up and down), press the "Actions for ..." key at the end of the row, or use Enter or Space on that key. Dragging is never the only way. Closed actions are out of the tab order. Esc closes the open row and returns focus to its key, choosing an action closes it, and only one row is open at a time.

Timeline

Events or steps in order, as a native <ol>, so a screen reader says how many there are and which one it is on. Each entry has a dot on a thin rail, in the style of the depth rail on the case studies at chrissimari.com. The state is in the shape of the dot, not only its color: a filled dot is done, a glowing ring (aria-current="step") is now, and a hollow ring (timeline__item--upcoming) is still to come. It is vertical by default; add timeline--horizontal to run it left to right from the md breakpoint up. On a phone it stacks, so it never needs sideways scrolling.

Forms

Checkboxes and switches

Native <input type="checkbox">. Checking latches the key down and lights its check mark; a switch is a checkbox with role="switch" and a cap that slides. Neither relies on color alone: the check mark and the cap's position carry the state.

Check list

A fieldset of native checkboxes (the WAI-ARIA Checkbox (Mixed-State) pattern). Add data-checklist and script puts a Select all box on top, checked when every item is and mixed when only some are, and a status line below that a screen reader announces politely ("2 of 4 done"). Disabled items are left out of the count. Without script it is a plain group of checkboxes.

Datalist and autocomplete

A text field with suggestions: add list to an input and point it at a <datalist> of <option>s. The field stays a plain input, so anything can still be typed, and the browser shows the matching suggestions as you type. The suggestion list is drawn by the browser (so it follows light and dark but not the rest of the theme), and it works on text, search, email, url, number, date, time and color fields. If a browser has no list support, it is just the field. For a themed list that filters as you type, add data-autocomplete (see Autocomplete below).

Search bar

The native <search> landmark around a form with one type="search" input, a leading icon and a Search key, so it submits and works with no script. Script adds a Clear key that shows once there is text: it empties the field, tells listeners with the input event and returns focus to the field, and Esc does the same. Name the landmark with aria-label, and keep a real label on the field (hidden here, because the placeholder is not a name).

Time picker

A native <input type="time"> stays the real field, so typing, step, min, max and forms work with no script. Script adds a clock key that opens a popover of choices: hours, minutes and, on a 12-hour clock, AM or PM. Every choice is a native radio drawn as a key, so the arrow keys move inside a group and Tab moves between groups; a choice writes the field at once. Esc or a click outside closes it and focus returns to the clock key. Minutes step by 5 unless you set data-minute-step (or a whole-minute step); a typed minute off the step is kept as a choice. The clock follows the page language, or set data-hour12. Seconds are not offered.

Rating

A row of stars that picks a score. They are native radios in a fieldset with a legend, so the arrow keys move the choice, the value submits and it works with no script. Each star is named in words ("3 stars"), a filled star differs from an empty one by shape, not only color, and a read-only rating-display writes the score out ("4 of 5") beside hidden stars.

Wizard

A form split into steps. Without script it is one long form with every step showing and the usual submit key. With script it shows one step at a time under a list of steps (done, current, upcoming), adds Back and Next keys, and moves focus to the new step's heading so it is announced. Next checks the current step's fields first, with the browser's own messages, and Enter inside a field does the same instead of submitting early. The last step keeps the form's own submit key.

Components

Accordion

Native <details> and <summary> in an .accordion. Items that share a name open one at a time; drop the name to let several stay open. No JavaScript.

What is simar-ui?

A set of UI components. Each one is a real HTML element underneath, so it still works without CSS or JavaScript.

Does it work with a keyboard?

Yes. Keys, faders and knobs all take focus and respond to the arrow keys, and every control shows a focus ring.

Can I change the colors?

The lit color, accent and cap tones are CSS custom properties, and data-lit or style="--lit: …" recolors any part of the page.

Alerts and toasts

An alert is a banner in the page with an icon, a title and some words, so the kind of message never depends on color alone. Add data-dismissible for a close button. A toast is the same banner shown for a few seconds in a live region, so it is announced without moving focus. It waits while the pointer or focus is on it, can always be dismissed (Esc too), and an error interrupts while the others wait their turn. Call SimarUI.toast("Saved", { variant: "success" }), or put data-toast on a button.

App bars

A bar that stays at the top or bottom of its scroll area: a native <header> or <footer> with position: sticky, so it needs no script and reads in order without CSS. The bars cover what scrolls beneath them, so the page gets scroll-padding and a focused control is never left hidden underneath (WCAG 2.2, Focus Not Obscured). This page's own header is one. Bottom navigation

The three to five main places of an app, in a bar at the bottom of the screen. It is a native <nav> with its own label and a list of links, drawn as the same keys as pagination: the place you are on has aria-current="page" and stays latched. The words always show beside the icon, so the link's name is its visible text. It works without JavaScript. Button group

A few related keys joined edge to edge in one well. Give the key-group a role and an aria-label so a screen reader says what the group is for. Use it for actions, for toggles (aria-pressed, which your script flips) or, with native radios, for choosing one. Only the two ends are rounded, and each key keeps its own states: the selected one stays latched.

Charts

A chart is a figure whose data is a native <table>. The table is the accessible version, so it works with no script. With the optional charts add-on it is drawn as a line, bar, pie or donut chart, named by its title and described by a short summary, and the table moves into a "Data table" disclosure for everyone to read. Each series has its own color, a dash pattern and a legend entry, so color is never the only clue. The drawing is done by Chartist (MIT), styled with the theme's tokens, so charts follow light, dark, palettes and styles.

Chips

Small keys that filter, choose or hold a value. Filter chips are native checkboxes (any number on) and choice chips are native radios (one on), so they submit, reset and work with no script, and a lit key means on. Input chips are values someone has entered, each with a Remove key: script takes the chip out, says so in a status line and moves focus to its neighbour; Delete or Backspace on the Remove key does the same. Without script, make the Remove key a submit button inside a form and the server drops the value. Give each group a name: role="group" for filters, role="radiogroup" for choices, an aria-label on the list for inputs.

Floating button

A key fixed to a corner of the screen, reachable from anywhere on the page: the "Turn JS off" button in this page's corner is one. Put a .key in a .well with the fab class. Bottom end is the default; fab--start moves it to the other side and fab--top to the top. fab--round makes an icon-only one, which needs an aria-label. It clears the notch and home bar on a phone, is hidden in print, and, because it floats over content, give the page fab-space so it never covers the last of the content on a small screen. Speed dial

A floating button that opens a short list of related actions. It is a native <details> with the key as its summary, so it opens and closes with no script (Enter, Space or a click). The actions are ordinary keys, links or buttons, with a visible label, and the first is nearest the key. Script adds Esc (closes and returns focus to the key), closing on a click or Tab outside, and closing after an action is chosen. Map

A map whose data is a list of places. The list is the accessible version and works with no script: each place has a link out to OpenStreetMap. With the optional maps add-on the places are also pins on a map, drawn by Leaflet (BSD-2-Clause) on OpenStreetMap tiles. The map is a labelled region: arrow keys move it and plus and minus zoom. The pins are real buttons. The zoom, pan and show-all keys are part of the map, so dragging is never the only way to move it, and each place in the list gets a "Show on map" button. The mouse wheel keeps scrolling the page, and on a touch screen one finger scrolls the page too. In the dark theme the tiles are darkened.

Side menu

A tab on the edge of the screen that opens a panel beside it, for options or navigation that should be one press away without taking room. This page's contents list (left) and settings (right) are side menus. It is a disclosure, not a modal: the tab is a button with aria-expanded and aria-controls, Esc closes the panel and returns focus to the tab, and so does moving focus out of it. Without JavaScript the panel simply shows in the page, in reading order. side-menu--start puts it on the left edge, side-menu--docked keeps the panel open as a column from the xl breakpoint up, and data-close-on-select closes it when a link inside is chosen.

Tooltips

Add data-tooltip to a button, link or radio key. It shows on mouse hover and on keyboard focus, Esc dismisses it, and you can move the pointer onto it. Give a key with no visible text an aria-label as well, so it has a name without JavaScript; then its tooltip is added automatically.
