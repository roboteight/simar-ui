Getting started

Install

Two files, no build step. Put these in the page, then write the markup below or the <simar-*> tags.

Or npm install simar-ui and import simar-ui/css and the script. Everything is configured with HTML attributes, listed under Configuration.

Declarative tags

Write a short tag and the script expands it into the markup shown in the sections above, so inputs still submit with their form. Options are attributes named like the native ones. These need JavaScript; the plain markup above doesn't.

Accessibility

simar-ui is built to be fully accessible, and checked on every change. Every control is a native element, so the keyboard, focus and screen-reader behavior comes from the browser, and the styling sits on top.

  • Keyboard. Everything is reachable and operable, and every stop shows a focus ring in both themes.
  • Names. Every control has a real label. Icon-only keys need an aria-label, and the library warns in the console, and outlines the control on localhost, if one is missing.
  • Color. Text meets WCAG AA in light and dark and every highlight. State is never color alone: it also has a check mark, a position, a pattern, or words.
  • No dragging required. Anything you can drag you can also set with a click or the keyboard.
  • Motion and contrast modes. prefers-reduced-motion and Windows High Contrast are supported, and everything degrades to native controls without JavaScript.
  • Tested. npm run test:a11y runs axe, contrast, WCAG 2.2 and keyboard checks in light and dark. Real screen readers, touch and Safari/Firefox still need a human pass.

Customize

Theme and color

Light and dark follow the system, or you choose with data-theme on <html> or any element. One value, --lit, recolors every lit part. Use the controls at the top of the page to try both.

Typography

Headings, display type, a lead paragraph, running text and inline marks. Use the classes anywhere (.h1 to .h6, .display-1 to .display-3, .lead), or wrap text in .prose to style the plain elements inside it. Keep the real heading levels in order on a page; the classes only change how a heading looks. Sizes scale with the window, so they fit a phone.

Layout and breakpoints

Mobile first, like Bootstrap: a class with no breakpoint applies everywhere, and one with a breakpoint (md) applies from that width up. The breakpoints are sm 36rem, md 48rem, lg 62rem, xl 75rem and xxl 87.5rem (576, 768, 992, 1200 and 1400px at the default size), and they are in rem, so they follow the reader's text size. Resize the window to see the columns below change. The class names and breakpoint approach are borrowed from Bootstrap, so they will feel familiar.

Datalist and autocomplete

A text field with suggestions: add list to an input and point it at a <datalist> of <option>s. The field stays a plain input, so anything can still be typed, and the browser shows the matching suggestions as you type. The suggestion list is drawn by the browser (so it follows light and dark but not the rest of the theme), and it works on text, search, email, url, number, date, time and color fields. If a browser has no list support, it is just the field. For a themed list that filters as you type, add data-autocomplete (see Autocomplete below).

Components

Accordion

Native <details> and <summary> in an .accordion. Items that share a name open one at a time; drop the name to let several stay open. No JavaScript.

What is simar-ui?

A set of custom-styled form controls. Each one is a real HTML element underneath, so it still works without CSS or JavaScript.

Does it work with a keyboard?

Yes. Keys, faders and knobs all take focus and respond to the arrow keys, and every control shows a focus ring.

Can I change the colors?

The lit color, accent and cap tones are CSS custom properties, and data-lit or style="--lit: …" recolors any part of the page.

Alerts and toasts

An alert is a banner in the page with an icon, a title and some words, so the kind of message never depends on color alone. Add data-dismissible for a close button. A toast is the same banner shown for a few seconds in a live region, so it is announced without moving focus. It waits while the pointer or focus is on it, can always be dismissed (Esc too), and an error interrupts while the others wait their turn. Call SimarUI.toast("Saved", { variant: "success" }), or put data-toast on a button.

Badge

A small label for a status or a count. It always has words, or a number with hidden words after it, so the kind never depends on color alone; the dot is decoration. Use badge--info, --success, --warning or --danger, and badge--count for a number.

Table

A native <table> with a <caption> and <th scope>. Wrap it in .table-wrap so it scrolls sideways on a narrow screen; the wrapper takes keyboard focus so the scrolling works without a mouse. Add table--striped or table--hover, and data-sortable with data-sort on the headers for sorting (the script adds the buttons and aria-sort).

Dropdown menu

A button that opens a list of actions or links. It is a native popover, so it opens, closes, dismisses on Esc and on a click outside without any JavaScript. The script adds the menu roles and keyboard movement: Enter, Space or the arrow keys open it, the arrows, Home, End and letters move, Esc closes and returns focus to the button, and Tab leaves.

Meter

A native <meter>: a gauge for a known quantity, as opposed to <progress>, which is work being done. The browser decides good, middling or poor from low, high and optimum, and the fill tells them apart by pattern (solid, striped, dotted) as well as color.

A native <progress>: it works without JavaScript and is announced as a progress bar. Leave off value when the length isn't known. Motion stops with prefers-reduced-motion, and data-paused freezes it.

Spinners

Four styles, all drawn as SVG so they stay crisp on any background: ticks, ring, dots and bars (variant on the tag, or a spinner--ring class). It is announced as a status, and with prefers-reduced-motion it shows a still "busy" arc instead of moving.

Tabs

Write each tab as a headed section. Without JavaScript they simply stack under their headings; with it, the headings become a row of keys and one panel shows at a time. Arrow keys, Home and End move between tabs, and the selected tab stays latched. Add data-selected to open on a different tab.

Tooltips

Add data-tooltip to a button, link or radio key. It shows on mouse hover and on keyboard focus, Esc dismisses it, and you can move the pointer onto it. Give a key with no visible text an aria-label as well, so it has a name without JavaScript; then its tooltip is added automatically.
